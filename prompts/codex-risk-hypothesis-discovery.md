# Codex リスク仮説生成の実験プロンプト

## 目的

通常のコードレビューで見落とされがちなリスクについて、**指摘の確定前に仮説をどこまで自力で生成できるか**を観察する。

これは本番用のレビューSkillではなく、Codexの仮説生成と探索の挙動を切り分けるための単発実験。設定ファイルや既存Skillの変更は不要。

## 実験用プロンプト

以下をCodexの通常セッションにそのまま貼り付けて実行する。

```text
現在のブランチとmainの差分を対象に、潜在的なリスクの探索を行ってください。

今回は通常のコードレビューではありません。バグの確定や指摘の絞り込みは行わず、変更によって起こり得る問題の仮説生成に集中してください。

以下の手順で進めてください。

1. 差分を読み取り、変更前後の振る舞いと、維持すべき不変条件を整理する。
2. 変更がどのような条件下で問題を引き起こし得るか、異なる故障メカニズムから仮説を発散させる。
3. 各仮説について、具体的な失敗シナリオと、その成立に必要な条件を示す。
4. 既存コードを追加調査し、発見した事実から新しいリスク仮説を生成する。
5. 仮説の検証・棄却・優先順位付けは行わない。

特定のチェックリストに限定せず、変更の性質に応じて探索観点を動的に選択してください。

最終出力は、リスク仮説、失敗シナリオ、成立条件、根拠となるコードの4項目で整理してください。

仮説が未検証であることは問題ありません。ただし、コードから導けない無関係な推測で件数を増やさないでください。
```

## 実施方法

- 比較するCodexとClaude Codeには、同じコミット・同じ差分・同じプロンプトを与える。
- 可能な範囲でモデル、reasoning effort、実行日時、既存のリポジトリ指示・Skillの有無を記録する。会社管理の環境設定を変更する必要はない。
- 既存のレビュー結果やClaude Codeだけが発見した問題を、Codexの実行前に教えない。
- 初回はリスク探索のみ行い、確定レビューや修正は別のセッション／工程に分ける。
- `main` が対象のベースブランチでない場合は、プロンプト内のブランチ名だけ置き換える。

## 観察・比較すること

| 評価軸 | 見るポイント |
| --- | --- |
| 仮説の多様性 | 異なる故障メカニズムに到達しているか |
| 仮説の具体性 | 失敗条件と具体的なシナリオが説明されているか |
| 調査の広がり | 初期差分から関連コードへ探索が広がっているか |
| 新規発見 | 従来のレビューにない妥当な懸念を見つけたか |

単純な仮説の**件数**では優劣を決めない。後から個々の仮説を検証して、実在する問題の検出・見落とし・誤検知を分けて評価する。

## 解釈の注意

- 仮説が増えた場合、通常レビューでは早期の絞り込みが起きていた可能性がある。
- 仮説が増えない場合、モデルの能力不足とは限らず、変更の理解・探索素材・指示の抽象度なども考えられる。
- 仮説は出るが見当違いな場合、根拠となるコード理解やコンテキスト収集を疑う。
- 会社の設定や既存の指示が残っている環境で実施した場合、これは「完全なピュアモデル比較」ではなく**普段の環境におけるプロンプト差分実験**になる。

## 次の実験

このプロンプトで改善が見られたら、`仮説生成 → 調査 → 新しい仮説生成 → 検証・収束` の分離をレビューSkillに組み込む。改善が乏しい場合は、調査事実の事前整理や、異なる視点からの独立した仮説生成を比較する。
